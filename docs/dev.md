## Repository layout

```
FFRArchipelago/            -> copy to ...\FFRS\Binaries\Win64\ue4ss\Mods\FFRArchipelago
  enabled.txt
  Scripts/main.lua         loop, item queue, checks, console commands
  Scripts/game.lua         engine calls (main file to update after a game patch)
  Scripts/bridge.lua       file link to the client
  Scripts/field_items.lua  generated by tools/gen_apworld_data.py (shiny ids and coordinates)
  Assets/                  Archipelago logo for the title screen
apworld/ff_resonance/      Archipelago world and client
  data.py                  generated by tools/gen_apworld_data.py; do not edit by hand
  client.py                Archipelago client (bridge files <-> server)
apworld/Final Fantasy Resonance.yaml   example player options
tools/fake_ap.py           fake Archipelago server for testing the mod alone
tools/gen_apworld_data.py  data/*.tsv -> apworld/ff_resonance/data.py and Scripts/field_items.lua
tools/build_apworld.py     apworld/ff_resonance -> dist/ff_resonance.apworld
tools/snapdiff.py          compares two ffrap_snapshot files
tools/crashstack.py        resolves UE4SS symbols in crash reports using UE4SS.pdb
tools/dump_game/           C# (CUE4Parse): game pak files -> dump/ (JSON; git-ignored)
tools/gen_from_dump.py     dump/ -> data/game/*.tsv, and --check against data/*.tsv
data/game/                 tables extracted from the game's pak files
data/chests.tsv            chest table export from in-game (ffrap_export)
data/shinies.tsv           shinies recorded in game
tests/                     automated test suite (run with python tests/run_all.py)
```

After `data/game/*.tsv` or `data/*.tsv` changes, run `python tools/gen_apworld_data.py` and commit the regenerated `apworld/ff_resonance/data.py` and `FFRArchipelago/Scripts/field_items.lua`.

## Game data dump

`tools/dump_game` reads the shipped pak files directly without starting the game and writes JSON to `dump/`. `tools/gen_from_dump.py` turns that into tables in `data/game/`, which `tools/gen_apworld_data.py` uses to build `data.py`.

```
dotnet run --project tools/dump_game -- all
python tools/gen_from_dump.py --check
```

Requirements and notes:
- Requires the .NET 10 SDK (or newer with `DOTNET_ROLL_FORWARD=Major`), a `Mappings.usmap`, and the Oodle DLL. By default, the tool picks up the newest usmap from `%LOCALAPPDATA%\FFR Modding Tools\workspace\mappings` or `FFRS\Binaries\Win64\Mappings.usmap`, and the Oodle DLL from FFR Modding Tools' `workspace\tools\oodle`. Pass `--usmap`, `--oodle`, `--game`, and `--out` to override.
- After a game patch, regenerate `Mappings.usmap` by enabling UE4SS's `UsmapDumperMod`, starting the game, waiting 30 seconds at the title screen, and turning the dumper back off.
- The tool reads only the base game paks (unencrypted), not `~mods` or `LogicMods`.
- Keep `dump/` out of git (roughly 110 MB of game data). Commit only the tables in `data/game/`.
- Supported commands: `all`, `files`, `enums`, `text`, `tables [filter]`, `maps [filter] [--classes regex]`, `assets <path prefix>`, `structs <regex>`, `raw <path>`. In Git Bash, set `MSYS_NO_PATHCONV=1` before passing a filter starting with `/`.

| File in `data/game/` | Contents |
|---|---|
| `items.tsv` | All 589 items across the six item tables (id, table, type, equipment detail, name, prices) |
| `units.tsv` | All 643 units: playable characters, guests, visions, summons, enemies, and bosses |
| `maps.tsv` | All 186 maps (id, key, English name, island, group) |
| `chests.tsv` | Chest table rows plus `boxes` (`level:uid`); rows with no placed box are not locations |
| `treasure_actors.tsv` | Placed treasure boxes (`m_Id`, level, position) |
| `field_items.tsv` | Placed field items, events, level, and position |
| `transitions.tsv` | Map exits: source map, destination map/point, and condition |
| `gimmicks.tsv` | Blockers, no-entry zones, doors, event triggers, save points, and airship landing points |
| `shops.tsv` | Shop stock, one row per item |

At runtime, the mod writes working files in its own folder: `ap_out.txt`, `ap_state.txt`, `ap_status.txt`, `settings.txt`, `ffrap_dump.txt`, `chests.tsv`, `seen.tsv`, and (when `ffrap_gate mark` is used) `crossings.txt`. `tools/fake_ap.py` writes `ap_in.txt` for standalone mod testing.

## Where the engine calls come from

The engine calls used by `FFRArchipelago/Scripts/game.lua` match behaviors observed in existing FFRS mods:

| Need | Call | Reference mod |
|---|---|---|
| Grant a bag item | `CPP_BFL_SaveDataInventory:AddInventory(id, n)`, `FindInventory(id)` | FFRSLib (`ffrs_grant_item`) |
| Unlock a vision | Grow `saveData.visionList`, set `ID`, copy `synchroPoints` keys, then `AddInventory(id, 1)` | FFRSLib (`ffrs_vision_unlock`) |
| Add a party member | `CPP_VM_Party:AddUnit(id)`, `IsJoinedUnit(id)` | FFRSLib (`ffrs_party_add`) |
| Story flags | `CPP_BFL_SaveDataProgress:SetFlag(i, bool)`, `GetFlag(i)` | FFRSLib (`ffrs_flag`) |
| Story counter | `saveData.Progress.Progress[1]` (1020 to 8050; thousands digit = chapter) | FFRSLib (`ffrs_story`) |
| Save data | `CPP_MuchaSaveDataManager.m_pGameSaveData` | FFRSLib |
| Opened chests | `CPP_BFL_SaveDataMap:IsOpenTreasureBox(mapId, uid)`; live `CPP_MapGimmick_TreasureBox.m_Id` / `m_IsOpen` | FFRS_QoL, FFRRandomizer probe |
| Shinies | `BP_MapGimmick_FieldItem*` actors with `m_UniqueId`; looted state via `IsOpenTreasureBox` | FFRS_QoL markers (based on ZArkadia's Item and Chest Markers, Nexus mod 25) |
| Chest table patching | `CDT_MapGimmickTreasureBox` and its parent tables | FFRRandomizer (`tableFamily`) |
| Loaded save slot | Save data object name; `Player.SavedDateTime.Ticks`; `GameSaveDataSummaryMap` slot summaries | FFRBestiary (`game.slotForTicks`) |
| Fallback on-screen text | `BP_ModSettings:Toast(msg, seconds, hue, worldContext)` | FFRSLib |

FFRSLib is part of FFR Modding Tools by Kanaruu. `FFRArchipelago` does not depend on FFRSLib, FFRS_QoL, or FFRBestiary at runtime (aside from optional `ModSettings` fallback toasts). Check FFR Modding Tools' and ZArkadia's Nexus permissions and credit requirements before publishing.

## Bridge format

Both bridge files (`ap_in.txt` and `ap_out.txt`) are append-only and tab-separated, one record per line.

`ap_in.txt` (client to game):
```
seed   <seed name>:<team>:<slot>                  first line; a new value starts the mod's state over
cfg    blank  <0|1>                               chest blanking
cfg    openworld <0|1>                            open-world mode
cfg    continent <name>                           starting continent
cfg    chocobo <0|1>                              start with Chocobo
cfg    airship <0|1>                              start with Airship
cfg    bosses <0|1>                               boss locations enabled
cfg    radar <0|1>                                radar treasure locations enabled
cfg    finalboss <chars> <visions> <fragments>    Crystal Tower seal thresholds
item   <index>  <kind>  <id>  <count>  <label>    kind: item | gil | vision | unit | flag | token
scout  <base64(key \t item \t player \t flags \t own)>  scouted reward text for chest pop-ups
msg    <text>                                     shown on screen
sync                                              report everything the save says is looted
bind                                              link the loaded save to this session
```

Each client session belongs to one save lineage. Starting **New Game (Archipelago)** links that save automatically; an existing save is linked by `bind`. The session tracks every slot that the linked game is saved to (`slots` in `ap_state.txt`) and drops a slot if another game overwrites it. While an unlinked save is loaded, the mod grants nothing, writes no `check` or `story` lines, and disables chest blanking.

`ap_out.txt` (game to client):
```
hello    <version>  <protocol>
seed     <session>                  subsequent lines belong to this session
check    chest:<row mapId>:<row ID> (rowless reward chests use chest:<map>:u<m_UniqueId>)
check    shiny:<map>:<m_UniqueId>
check    boss:<battle group>
check    radar:<1..13>
story    <counter>
won      <battle group>             9056: final battle (Rain vs. Sol)
applied  <index>  <ok|fail>  <detail>
```

The client only processes `check`, `story`, and `won` lines after a `seed` line matching its own session. Starting a new session clears `ap_out.txt`. `<map>` is always the map id returned by `CPP_MapManager:GetSameMapId()`.

## seen.tsv

The mod appends one line the first time it sees each chest or shiny across sessions, building a location and save-key map:

```
kind  map  uid  row  item  count  money  visible-condition
```

`kind` is `chest` (has a table row), `xchest` (no row), `shiny`, or `spot` (a shiny-class story or quest point with no reward). `map` and `uid` are the save's key. For chests, `row` is `mapId:ID`; for shinies, it holds the Blueprint class.

## Console commands

These commands run in UE4SS's `ConsoleEnablerMod` console for development and debugging (likely to be disabled for production releases):

| Command | What it does |
|---|---|
| `ffrap_status` | Logs and prints what the mod sees right now |
| `ffrap_grant <kind> <id> [n]` | Grant directly without the bridge: `item`, `gil`, `vision`, `unit`, `flag` |
| `ffrap_dump [rows]` | Chest and shiny discovery dump to `ffrap_dump.txt` |
| `ffrap_export` | Export every chest table row to `chests.tsv` |
| `ffrap_blank [on\|off]` | Toggle chest blanking (chests that are AP locations give 1 gil; id 13000+ except Magicite keep vanilla) |
| `ffrap_sync` | Report every location in `seen.tsv` that the loaded session save marks as looted |
| `ffrap_bind` | Link the loaded save to the client's session (same as `/bind` in the client) |
| `ffrap_reset` | Reset the loaded save's applied-item count to 0 so all received items re-apply |
| `ffrap_snapshot [name]` | Dump every field of the loaded save to `snap_<name>.tsv` (compare with `python tools/snapdiff.py`) |
| `ffrap_functions [class ...]` | Dump class functions and parameters to `functions.txt` |
| `ffrap_inspect <class or path> [label]` | Dump an object's fields and functions to `inspect_<name>[_<label>].tsv` |
| `ffrap_find <text>` | Search native/Blueprint classes, functions, and fields matching `<text>` to `find_<text>.txt` (run in-game; crashed once at title screen) |
| `ffrap_skip [slot] [force]` | Skip the prologue on a new game after story 1005 (`force` skips earlier, leaving opening input lock) |
| `ffrap_input [fix]` | Inspect or attempt to reset the player controller's input lock state |
| `ffrap_openstart [on\|off\|dock\|air\|event\|at x y z\|now [slot]]` | Configure or trigger the open-world start probe |
| `ffrap_chats [done]` | List Active Time Chats on the loaded save, or mark all played |
| `ffrap_visions` | Log the first vision's synchro keys |
| `ffrap_lock [on\|off\|open <continent\|all>\|close <continent\|all>]` | Toggle or test continent landing/crossing locks |
| `ffrap_title [list\|add]` | List title menu entries or manually add the Archipelago entry |
| `ffrap_notice [text]` | Experimental quest-notice banner test |
| `ffrap_logo` | Manually place the Archipelago logo on the title screen |
| `ffrap_layout <text>` | Log widget panel chain containing `<text>` |
| `ffrap_feed [on\|off\|test [plain]\|check]` | Configure or test the bottom-right HUD item feed |
| `ffrap_scale <level\|low high\|party [range]\|off> [at %] [hp %] [attack %] [magic %] [power %] [boss] [follow]` | Manual enemy scaling probe in `DT_UnitParameter` (`show <id\|name>` inspects rows) |
| `ffrap_noland <list\|here\|show [width]\|hide\|lock <box>\|unlock <box>\|refresh\|spawn [half] [top]\|move [half]\|channel <n> <0-2>\|cond <text>\|off>` | Probe and visualize `BP_MapNonLandingArea_C` airship no-landing boxes |
| `ffrap_story [value]` | Set the loaded save's story counter (save and reload to apply; use on an unlinked save) |
| `ffrap_airship [condition\|off\|state\|home]` | Inspect or rewrite `DT_MapAirShip` spawn condition, or park a seed's airship at its start (`home`) |
| `ffrap_bossfight <battle group> [quiet]\|sword\|off\|watch [class ...]` | Experimental boss trigger / talk event hook test |
| `ffrap_set [exp\|gil\|mrp\|encounterrate <number>] [encounters\|scaling <on\|off>] [strength casual\|normal\|expert] [reset]` | View or set player gameplay settings in `settings.txt` |
| `ffrap_menu add\|dump` | Manually add `AP:` rows to Options > Gameplay, or dump option save entries |
| `ffrap_gate <subcommand>` | Experimental blocker probe and world-map bridge crossing placement (`mark`, `unmark`, `crossings`, `move`, `turn`, `size`) |
